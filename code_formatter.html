貼上舊版程式碼，統一縮排、空格、換行與格式；格式化前後可逐行對照，並附帶語法檢查（含行號與欄位）。

主題：
隱私：程式碼只在你的瀏覽器內處理，本頁不會把程式碼上傳到任何伺服器，也沒有自建後端。格式化與檢查引擎是公開的程式庫，會在第一次用到時從 unpkg.com、cdn.jsdelivr.net、esm.sh 下載（CDN 看得到你的 IP 與請求的套件檔名，看不到程式碼內容）；本頁以 CSP 限制只能連線到這三個 CDN。各引擎的來源與載入狀態見下方「外部 CDN 依賴」。

使用說明與限制

  1. 先選擇正確的程式語言，再按「格式化程式碼」。語法有誤時會中止並在 Console 顯示行號與欄位，點「第 N 行 第 M 欄」可跳到原始碼對應位置。
  2. 引擎：HTML／JS／TS／CSS／JSON／YAML／Markdown／JSX／SCSS／Less／Vue／Angular 使用 Prettier；SQL 使用 sql-formatter；Python 使用 Ruff（Rust 編譯成 WebAssembly，格式接近 Black）；Java／C／C++／C# 使用 clang-format（WebAssembly）。
  3. 語法檢查：Python 用 Ruff 的瀏覽器端解析器；Java／C／C++／C# 用 tree-sitter 解析器（只判斷「語法」，不檢查型別、符號或語意）；Prettier 支援的語言直接取用其解析器的錯誤位置。這些都不能取代 python、javac、GCC／Clang、dotnet 等真正的編譯器。
  4. C／C++ 的巨集與條件編譯、C# 較新的語法，可能被誤判為語法錯誤；此時可勾選「語法檢查未通過仍嘗試格式化」。clang-format 對 C# 的支援比 C／C++／Java 陽春。
  5. clang-format 已設定不重排 #include／import／using，只調整排版；格式化只改版面，不保證功能完全不變，請先看差異並實際編譯測試。
  6. SQL 方言差異很大，請選對方言；格式化不會連線資料庫，也無法確認資料表或欄位是否存在。
